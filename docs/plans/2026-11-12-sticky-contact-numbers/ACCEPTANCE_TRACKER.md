## Required clarifications carried from the conditional approval

A04 needs a real send initiated from the Dialer through existing shared infrastructure, not a label. C04 needs a separate inbound qualification path. Historical outbound backfill must not require new bindings that did not exist or fabricate them. B08/B09/B12 and E14 include late evidence that changes outside calls, equal duplicate facts, processor failures and enqueue failures; created_at-only scanning is insufficient.

E02/E03 cover immutable intent AND old-hash compatibility: an old accepted receipt must replay safely, and a changed explicit sender/override is different intent. A default/readiness change cannot silently rebind an existing request. E05/E06/E11/E16 cover readiness failure after reservation, definite pre-handoff cancellation, uncertain acceptance and old-package behavior.

D04/D06/D07/D12/D15 require actual database-role execution and negative tests for private helper invocation, grants, inaccessible/ambiguous unsaved calls and shared-contact edit authority. A private schema or invoker wrapper alone does not prove these cases.

F13 includes enforced→guard_only→off/shadow, settings deletion/recreation and read errors. Voice rotation under guard_only is allowed only for proven-new endpoints; historical/review/pending-evidence endpoints cannot be treated as no pin. G01/G07 cannot label missing setup as work in progress.

F11 includes separately approved live release checks; it remains pending until those are actually authorized and executed. A ready-to-review isolated candidate must clearly distinguish local proofs from remaining production proofs, not silently mark live tests complete. There is no requirement to execute unauthorized pilot actions just to make the tracker green.
