## 3. Server design

Conventions:
- Owner `postgres`; `SET search_path = pg_catalog, pg_temp`; qualified names. Actor `private.campaign_actor()`; errors 42501, 22023 and PT409. Reader helpers are INVOKER. No RLS change.
- Every created function gets `REVOKE ALL … FROM PUBLIC, anon, authenticated, service_role` in its creating migration. GRANTs appear only as the file's privilege class allows (§2.8):
  - class C (no GRANT): `…13`, `…40`, `…43` and every rollback file;
  - class W (the listed RPCs TO authenticated only): `…41`, `…42` and `appointment_evidence_enable.sql`;
  - class E: `…44`;
  - class R (REVOKE only, or no privilege statement at all): `appointment_evidence_disable.sql`, the read-only `reporting-accuracy/appointment_evidence_preflight.sql`, and the category baseline and revert scripts (data writes with no GRANT).
- Evidence tables live in `private`: RLS on, no policies, REVOKE ALL including service_role, no FK to `wins` or telephony tables (C2-09). Their indexes are created transactionally in the same migration, which §2.7 allows only for private tables.

**Trigger** `appointments_v3_evidence_capture AFTER INSERT OR UPDATE OR DELETE ON public.appointments FOR EACH ROW`. It fires on every write, so reconciliation can rely on the server-maintained `updated_at`. The conversion's `contact_id` move (`20261021200000:301`) now writes observations only, and still succeeds (E9).
```sql
CREATE FUNCTION private.appointment_evidence_capture() RETURNS trigger
LANGUAGE plpgsql SECURITY DEFINER
SET search_path = pg_catalog, pg_temp
SET lock_timeout = '200ms'                 -- function-level: applies only while this function runs
AS $$
DECLARE r public.appointments := CASE WHEN TG_OP = 'DELETE' THEN OLD ELSE NEW END;
BEGIN
  IF nullif(current_setting('agentflow.appointment_outcome_request', true), '') IS NOT NULL THEN
    PERFORM private.appointment_evidence_apply(TG_OP, OLD, NEW); RETURN NULL;   -- outcome RPC: evidence-first, fails closed
  END IF;
  BEGIN
    PERFORM private.appointment_evidence_apply(TG_OP, OLD, NEW);
  EXCEPTION WHEN OTHERS THEN               -- every error except QUERY_CANCELED and ASSERT_FAILURE
    BEGIN INSERT INTO private.appointment_evidence_capture_gaps(organization_id, appointment_id, sqlstate, operation)
          VALUES (r.organization_id, r.id, SQLSTATE, TG_OP);
    EXCEPTION WHEN OTHERS THEN RAISE WARNING 'appointment evidence gap not recorded (%)', SQLSTATE;
    END;
  END;
  RETURN NULL;
END $$;
```
**Failure classes (§2.12):**
- **Caught.** `OTHERS` catches everything else, including a lock timeout (55P03). The capture rolls back to its savepoint, a gap row is written in a nested block where possible, and the appointment write commits. If the gap write also fails, only a WARNING remains. The reader then shows the row as `capture_gap` wherever a durable source survives (§3.6); the one unobservable case is disclosed and never claimed as detected (BC5).
- **Not caught.** `QUERY_CANCELED` (statement timeout or `pg_cancel_backend`, 57014) and `ASSERT_FAILURE` abort the whole statement atomically: no booking, no evidence. The caller receives the error and the existing idempotent retry applies: `persist_booking` replays by request id, and a Dialer wrap-up keeps its draft (#39). Cancellation is never caught.
- **Bounded.** `appointment_evidence_apply` (DEFINER) takes a per-appointment advisory lock, which the 200 ms `lock_timeout` covers. It does only primary-key or unique lookups (the org's few types are read by name) and single-row writes. Harness budget: p99 < 20 ms at gate scale.

The actor is `auth.uid()` (NULL = system: the Google service role, ops). Status keys are `lower(btrim)`: completed → held; no-show variants → no_show; cancelled/canceled → cancelled; scheduled/confirmed → open; anything else is ignored.

**Transitions** (the system actor's behaviour in brackets):
- **INSERT:** observation; open seq 1 (`booking`) with snapshots (kind, created_at, setter, assignee, contact, type, category). A terminal status also writes `booking_entry` [`external_sync`; Google imports `other`].
- **Every UPDATE:** observation. If there is no occurrence, or the open slot ≠ `OLD.start_time`: open one from OLD (`pre_capture`; drift closes the stale one as `capture_gap`), then apply the change.
- **`user_id` changed:** assignment event.
- **Start moved:**
  - from open to terminal in the same write → close `slot_corrected` and record the outcome on seq+1;
  - otherwise close `rescheduled_before_start` if `clock_timestamp() < OLD.start_time`, else `rescheduled_after_start` (outcomes kept);
  - then open seq+1 from NEW [the system carries the category forward].
- **Status:** open→terminal writes an event (`status_edit`, or `outcome_action` under the GUC); terminal→terminal supersedes; →open writes `retracted` [system: only →Cancelled].
- **Type changed by a human:** a new category snapshot on the observation; with an outcome, also a superseding `reclassified` event [system: ignored]. A same-name type carries the occurrence's type id forward.
- **Other columns only:** observation only.
- **DELETE:** observation; close `deleted`; events kept.

**`public.record_appointment_outcome(p_request_id uuid, p_appointment_id uuid, p_expected_start timestamptz, p_outcome text) RETURNS jsonb`** (INVOKER; `GRANT EXECUTE … TO authenticated` only):
1. `held|no_show` and `now() ≥ p_expected_start`, else 22023.
2. Sets the GUC `agentflow.appointment_outcome_request`, runs `UPDATE public.appointments SET status = 'Completed'|'No Show' WHERE id … AND organization_id = get_org_id() AND start_time = p_expected_start` under the `appointments_update` RLS (#22: no definer path), then resets the GUC.
3. 0 rows → PT409 "Appointment changed or is not available. Refresh and try again."
4. The trigger validates the GUC, stamps `request_id` and `recorded_by = auth.uid()`, and fails closed: a lock timeout raises 55P03 and changes nothing. Credit is unaffected.
5. A replay is a no-op with the same body; a different outcome on the same request → 22023.

**Reconciliation (§2.12, BC5).** Completeness is never inferred from the absence of gap rows. Detection depends on a durable source surviving: the current appointment row (state, `updated_at`, existence), a booking receipt (`private.booking_receipts`, written by `persist_booking` and `save_disposition_with_booking`), and earlier evidence rows. Each observation stores the previous and new row state, and `updated_at` is server-maintained (`appointments_updated_at`). A population appointment is a `capture_gap` when any of these holds:
1. Its current row differs from its last observation, or the observation chain breaks: an observation's previous state differs from the prior observation's new state, or a pre-capture row's first previous `updated_at` is later than `cap_start`.
2. It was created at or after `cap_start` without an INSERT observation (no booking evidence), seen from its current row or its booking receipt; or it is a pre-capture row without any observation whose `updated_at` is later than `cap_start`.
3. Earlier evidence or a booking receipt says it existed, but the row is gone without a DELETE observation.
4. A gap row names it.

A window that overlaps a disabled interval carries `capture_gap` at window level. **Known unobservable case (BC5):** an appointment inserted and then deleted while both capture paths failed, by a writer that leaves no receipt (a Calendar UI insert or a Google inbound-sync insert), leaves no durable source. It is disclosed in How it's calculated ("Appointments created and removed while capture was failing cannot be detected") and never claimed as detected; no tracking subsystem is added to close it. For 12, 16, 17 and 18, gap items are unassessable and leave the value. A KPI 15 gap booking is counted (RL-42): the window is Partial, with its count in `coverage.reasons.capture_gap` and `unassessable` 0.

Tests run in both directions:
- **S14a:** appointments, outcomes, attributions and sales on unrelated identities (no in-scope credited event) leave personal and team payloads byte-identical apart from `as_of`. The same holds for matching activity in another organization.

## 10. Risks
- **Non-blocking capture can turn a systemic bug into gaps.** Reconciliation shows a lost write as `capture_gap` wherever a durable source survives (the current row, a booking receipt or earlier evidence). A create-then-delete by a no-receipt writer while both capture paths fail is undetectable; it is disclosed, never claimed as detected (BC5). The read-back requires 0 gap items, and the disable script is prepared. Cancellations and timeouts still abort the write, as today.
- **The trigger now fires on every appointment write**, one subtransaction per row. Bulk moves are rare, and conversion moves only a contact's rows. The performance gate runs 10k appointments per org, with p99 capture < 20 ms.
- **Stale re-saves.** Old tabs, or a modal left open, can re-save an open status after an outcome; that is recorded as a human `retracted` event. The outcome panel closes the modal on success.
- **Adoption.** If agents rarely record Held/No show or link policies, 16–18 and 12 stay partial (or unavailable when nothing is resolved). The closing field is optional, so unlinked sales leave members unresolved until they are linked later.
- **KPI 15 legacy basis.** Legacy rows (before booking receipts began with `20261005161629`) are classified from their current type, because retyping is unknowable for them. They are counted and disclosed through the window-level `legacy_booking_basis`.
- **Google sync** still overwrites the type and status shown in the Calendar (pre-existing). Reports are protected because system actors cannot retract or reclassify.
- **Legacy callback signature (D-C4).** It relies on literal titles; a real sales meeting titled "Callback" would be excluded (disclosed).
- **First-classification rule (D-C1).** A custom type's first classification applies to bookings made while it was unclassified. A later reclassification never rewrites snapshots, and a reverted baseline is skipped.
- **Credit is a proxy.** The assignee at start is not proof of attendance; this is labelled. With no trustworthy assignee at start, nobody is credited individually; the item stays in agency totals only (BC3).
- **The basis-flags preimage depends on package order.** The second of PKG-C/PKG-D regenerates it at release preparation.
- **Generated Supabase types are stale.** New RPCs use the existing narrow `(supabase as any).rpc` cast.
- **Replica drift.** The appointment visibility replica can drift from `appointments_select`; the pinned md5 fails CI until the replica is reviewed.
- **`clients.lead_id` stays mutable until PKG-C's guard** if PKG-D lands first. Link validation still requires a caller-visible, held, sales-category occurrence with `sold_date` on or after it.
- **Teardown.** Evidence tables are not removed by `wipe_organization_operational_data`; org teardown needs a separate ops review.
- **RLS-limited candidates.** The browser candidate list follows RLS: a Team Leader cannot link an appointment outside their team (fails safe: the member stays unresolved).
- **Reconciliation cost** grows with observations per appointment. Private indexes on (org, appointment_id, observation order) keep it inside the gate.
- **Workflow trigger.** The `appointment_no_show` workflow trigger never fires for a UI 'No Show' (baseline:3421-3425). It is out of scope, unchanged and not used as evidence.
