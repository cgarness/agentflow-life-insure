# D5. Regional performance (U.S. state heatmap), revised

## 1. Overview

Regional performance is section 5 of the one-page Reports V2 page (brief §18, main plan §2.16). It sits after Agent performance and before the Calling heatmap. It shows a U.S. state map, an equivalent table and an unmapped reconciliation row. There are four modes: **Calls made** (the default), **Contacted calls**, **Policies sold** and **AP** (brief §20).

- **One secured aggregate reader**, `public.get_report_state_breakdown_v3(date, date, uuid, text)`. It is reader 5 of the nine v3 readers (§2.1), with panel key `states`.
  - D5 writes its body inside D1's `…15_reports_v3_readers.sql`, which holds all nine readers.
  - D5's two helpers and its one index live in `…14_reports_v3_state_helpers.sql` (§2.6, §2.7).
  - Both files are privilege class C (§2.8). Every D5 object is created sealed with `REVOKE ALL … FROM PUBLIC, anon, authenticated, service_role`, and D5's SQL contains no GRANT.
  - EXECUTE on the reader comes only from the class E enable: `supabase/ops/reports_v3_enable.sql` and its byte copies `…17`, `…22`, `…33` and `…44`. It grants exactly the 15 report readers (6 v2 + 9 v3, the state reader among them) TO authenticated, service_role (A-41).
  - D5 has no ops file and no rollback file of its own.
- **The same populations as the KPIs, by construction.** KPIs 1, 2, 5 and 6 come only from `get_report_summary_v3`. The state reader returns `metrics: []` and only splits those totals by state (X12).
  - Calls: `private.report_v3_call_facts(p_org, p_start, p_end)` WHERE `is_attempt`, credited to `placing_agent_id`. `is_attempt` is `direction_class = 'outbound' AND attempt_class = 'attempt'` (§2.10), so only pre-admission rows and admitted rows count. The org A all-time total is **8,355** (5,058 pre-admission + 3,297 admitted).
  - The 3 refused non-attempts and the 9 unverified rows are excluded from the map, exactly as from KPI 5. The payload discloses them in its `call_population` block, which carries the same counts as KPI 5 `detail.call_population`. Raw rows are never changed.
  - Policies: `private.report_v3_sale_facts(p_org, p_agents, p_sold_from, p_sold_until)` over `private.report_v3_sold_window`, filtered `recorded_at <= now()` (X14) and credited to the original seller.
  - `totals` equal summary KPIs 5, 6, 2 and 1, and each mode carries its KPI's status and reason.
- **State attribution.** No state is captured when a call is made or a sale is recorded. The map therefore groups by recorded state and never describes historical grouping as event-time residence (§4.1). Priority order:
  1. event snapshot (none exists; PKG-E is deferred and would need its own approval);
  2. the current recorded state of the D3 identity's same-org lead/client records;
  3. a narrow campaign-membership copy, used only when those records exist and are all blank.

  Steps 2 and 3 are the recorded-state fallback that makes the map functional without PKG-E. The in-scope event is grouped by the identity's current recorded state, whoever set it, including a campaign-membership copy reached through any same-org call on that identity. This is privacy effect E4 (§2.9), and it applies under every ★1 option.
- **Grouping.** Each call and each policy gets at most one state. Calls and policies are grouped separately. For every mode, Σ51 states + unmapped = totals.
- **Map.** A static SVG path module generated from `us-atlas@3.0.1` (ISC licence; Census 2017 cartographic boundaries). It is lazy-loaded and adds no new dependency. Its provenance is recorded by an isolated documentation task (§5) that blocks only the PKG-F map merge.

### 3.2 `private.report_v3_state_classify(p_raw text, OUT state_code text, OUT reason text)`
- `LANGUAGE sql IMMUTABLE PARALLEL SAFE SET search_path = pg_catalog, pg_temp`, invoker.
- Steps:
  1. Trim (D5-1).
  2. Empty → `missing_state`.
  3. Otherwise call `public.normalize_us_state(v)`, unchanged (baseline `:4378-4470`; unrecognized input is returned as is).

### 3.3 `private.report_v3_identity_states(p_org uuid, p_identity_keys text[])`

It reads at most one converted client per lead, which `uq_clients_lead_id` guarantees; the `…14` preflight refuses to install without that unique index.
- Keys are D3's `lead:<root>` and `client:<id>`. Malformed keys are dropped. Every join is `organization_id = p_org`. Results are all-time and do not depend on the window or scope.
- **Batch 7, typed inputs (access path only).** The rules run in `private.report_v3_identity_states_by_id(p_org uuid, p_lead_ids uuid[], p_client_ids uuid[])`, which returns `(identity_kind, identity_id, state_code, reason, basis, last_state_change_at)`: one row per distinct id, NULL ids dropped, keyed by (kind, id) throughout, PARALLEL RESTRICTED. The key form parses its keys exactly as before and reads it, so both give the same states. The state reader passes the typed ids directly: no text key is built, parsed or compared on its path.
- **Parallel safety (Batch 7 checkpoint review, 2026-11-03).**

### 3.4 `public.get_report_state_breakdown_v3(p_start_date date, p_end_date date, p_agent_id uuid DEFAULT NULL, p_requested_scope text DEFAULT NULL)`
`RETURNS jsonb LANGUAGE plpgsql STABLE SECURITY DEFINER SET search_path = pg_catalog, pg_temp`, owned by `postgres` and created sealed. It takes no org, time zone or as_of argument; `as_of = now()`. It runs §2.1's checks in order, then computes.

```sql
a  := private.report_access_v2(p_requested_scope, p_agent_id);      -- 42501; a.org_id, a.agent_ids (NULL never widens)
w  := private.report_window(a.org_id, p_start_date, p_end_date);    -- 22023, then 55000
sw := private.report_v3_sold_window(w.start_date, w.end_date, (now() AT TIME ZONE w.time_zone)::date);
out_f MATERIALIZED: SELECT created_at, attempt_class, is_attempt, is_contacted, identity_key
   FROM private.report_v3_call_facts(a.org_id, w.start_at, w.end_at)     -- reviewed duplicates already excluded
   WHERE direction_class = 'outbound' AND (a.agent_ids IS NULL OR placing_agent_id = ANY(a.agent_ids))
calls_f := out_f WHERE is_attempt                                         -- attempt class only (§2.10)
call_population := {attempts, non_attempts, unverified} counted by attempt_class over out_f,
                   plus duplicates_excluded, exactly as KPI 5 detail.call_population (D3)
pol_f MATERIALIZED: SELECT recorded_at, monthly_premium, premium_state,
          private.report_v3_client_identity_key(a.org_id, buyer_id) AS identity_key
   FROM private.report_v3_sale_facts(a.org_id, a.agent_ids, sw.sold_from, sw.sold_until)
   WHERE recorded_at <= now()                                             -- X14, as KPIs 1 and 2
ist MATERIALIZED: private.report_v3_identity_states(a.org_id, distinct lead:/client: keys of calls_f ∪ pol_f)
   -- Batch 7: report_v3_identity_states_by_id(a.org_id, lead ids, client ids) of the same identities; a buyer's
   -- identity is report_v3_client_identity_key's rule, typed (the same-org client's root lead, else the client)
per row: reason = 'non_prospect_contact' (recruit: key) | 'unresolved_identity' (NULL key or no ist row) | ist.reason;
         changed_after = basis='current_record' AND last_state_change_at > created_at | recorded_at
call_g, pol_g: grouped separately by (state_code, reason); pol_g counts known/missing/invalid and sums known monthly_premium × 12 in exact cents
jurisdictions = 51-row VALUES LEFT JOIN call_g LEFT JOIN pol_g; unmapped = 6-row VALUES; totals from calls_f/pol_f
RETURN private.report_v3_envelope('state_breakdown', …) || {state_basis, metrics:[], modes, call_population, jurisdictions, unmapped, totals}
```

- **Sold window.** `report_v3_sold_window` returns `(sold_from, sold_until)`, half-open (§2.6). A future-dated Sold Date counts once its date arrives, as in KPI 2.
- **AP per group.**
  - 0 when the group has no policies.
  - NULL when it has policies but none with a known premium.
  - Otherwise Σ known `monthly_premium` × 12, in exact cents. D2's sale facts are cents-exact (live exceptions: 0 of 35), and the server never rounds this sum (§2.5), so the per-state values sum to KPI 1 to the cent.
- **Modes.** Each mode carries its KPI's status and reason for the same window and scope. Codes come only from the 29-code registry (§2.3).
  - `calls_made` (`metric_id 5`) = KPI 5, whose rule D3 owns (coverage: eligible = attempts + unverified, assessable = attempts; §2.10). It carries `attempt_unverified` whenever `call_population.unverified > 0`: `partial` when `attempts > 0`, and `unavailable` when `attempts = 0` (§2.2 rules 2 and 3). Otherwise it is `available`, including `available 0` on an empty window.
  - `contacted_calls` (`metric_id 6`) and `policies_sold` (`metric_id 2`) are counts with no coverage population (§2.4). They are always `available`, with reason null, and `available 0` on an empty window, because their evidence is complete: unverified rows can never be contacted (§2.10).
  - `ap` (`metric_id 1`) applies KPI 1's rule (§2.2 truth table, RL-11) to the same totals. Usable premiums are those with `premium_state = 'known'`. `premium_invalid` precedes `premium_missing` in the registry (§2.3):
    - policies = 0 → `available`, $0.00;
    - usable premiums = 0 (policies > 0): if any premium is invalid → `unavailable/premium_invalid`; otherwise → `unavailable/premium_not_entered` (X14; a coverage code with assessable = 0 is allowed by §2.2 rule 2);
    - some usable premiums: `partial/premium_invalid` if any premium is invalid, else `partial/premium_missing`;
    - every premium usable → `available`.
  - A zero value never replaces an evidence state (§2.2 rule 5).

### 3.5 Payload (§2.1)
- **Top level** is D1's meta from `private.report_v3_envelope` (§2.1):
  - `basis_version: 'reports_v3'`;
  - `contract_version` from `report_v3_basis_flags()`: 3.0.0 at PKG-A, then a minor bump per package, at least 3.3.0 when PKG-F ships. Zod accepts `^3\.\d+\.\d+$`;

  - `window` (verbatim `report_meta`);
  - `as_of`, `agency_today`, `period_open`;
  - `basis: {corrections, sale_call_links, appointment_evidence}`;
  - `policy_basis: {source, credit, date, premium}` (X13).
- **The reader adds:**
  - **`state_basis`** `{version:'state_v1', priority:['event_snapshot','current_record','campaign_copy'], event_snapshot_available:false, campaign_copy_fallback:true, normalizer, classifier:'report_v3_state_classify_v1', history_capture_since:'2026-10-03'}`. This is the state reader's own basis marker. D5's schema adds it to D1's meta for this reader only.
  - **`metrics: []`**.
  - **`modes`** `{calls_made:{metric_id:5, status, reason}, contacted_calls:{metric_id:6, …}, policies_sold:{metric_id:2, …}, ap:{metric_id:1, …}}`.
  - **`call_population`** `{attempts, non_attempts, unverified, duplicates_excluded}`: the same counts as KPI 5 `detail.call_population` for this window and scope (§2.1 row 5, §2.4, §2.10). `attempts` = `totals.calls_made`.
  - **`jurisdictions`**: exactly 51, sorted, zero-filled. Each is `{state, calls_made, contacted_calls, policies_sold, premium:{policy_count, known_count, missing_count, invalid_count, annual_premium}, basis:{calls:{event_snapshot, current_record, campaign_copy}, policies:{…}, calls_changed_after_event, policies_changed_after_event}}`.
  - **`unmapped`** `{calls_made, contacted_calls, policies_sold, premium, reasons:[missing_state, invalid_state, unresolved_identity, source_conflict, unsupported_geography, non_prospect_contact]}`, in that fixed order.
  - **`totals`** `{calls_made, contacted_calls, policies_sold, premium}`.
- There is no top-level `time_zone` or `period`.
- The unmapped reasons are a separate closed enum (`STATE_UNMAPPED_REASONS`), not envelope reason codes.
- No ids, names, phone numbers or row timestamps appear in the payload (AGENT_RULES.md:509; §2.9).

### 3.6 Invariants
- **Cardinality:** one row per call and one per policy.
- **Reconciliation:** Σ51 + Σ6 reasons = totals for every count, and for AP to the cent.
- **Cross-reader** (§2.10, X12; per window and scope, same `as_of`):
  - `totals.calls_made` = KPI 5 (`get_report_summary_v3`) = Σ heatmap.calls_made = Σ by_date (`get_report_call_volume_v3`). This is the "state total" at the end of §2.10's chain;
  - `call_population` = KPI 5 `detail.call_population`, and v2 `calls_made` − `totals.calls_made` = non_attempts + unverified;
  - contacted = KPI 6 = Σ heatmap.contacted;
  - policies = KPI 2;
  - AP = KPI 1 to the cent;
  - `modes.calls_made` = KPI 5 and `modes.ap` = KPI 1, in status and reason.
- Tests check these in one SQL transaction, so every reader sees the same `now()`. The production read-back does the same (brief §20).

### 3.7 Security and privacy (§2.8, §2.9)
- Only the reader is a definer, and it is owned by `postgres`. The helpers are invoker and never granted, and client roles never get USAGE on `private`.
- **Privileges** (§2.8). `…14` and `…15` are class C. The reader is one of the 15 readers in the class E allowlist, TO authenticated, service_role. The effective-privilege matrix (S1–S3, S15) covers the reader in every state:
  - enabled: executable by authenticated and service_role, and by a role that inherits authenticated;
  - v3 disabled (`reports_v3_disable.sql`): not executable;
  - all disabled (`reports_all_disable.sql`): not executable;
  - rolled back: absent.

  anon, PUBLIC and every client role on the helpers are false in every state.
- Scope comes from `report_access_v2`, and `p_agent_id` only narrows it. Errors keep §2.1's order: 42501, then 22023, then 55000.
- **Populations are credit-scoped.** Calls are credited to in-scope placing agents and policies to in-scope original sellers. Identity-state lookups are keyed only by the identities of those rows. Cross-organization rows are never read. Unmapped, basis and `call_population` counts cover only in-scope credited items.
- **S14a (unrelated identities).** Activity on identities with no in-scope credited event leaves every personal and team state payload byte-identical apart from `as_of`. This covers out-of-scope agents' calls of every attempt class, contacted and unresolved calls, sales, links and state changes, and matching activity in another organization.
- **S14b (linked in-scope identities).** Out-of-scope activity changes a scoped state payload only through E4: the in-scope event is grouped by the identity's current recorded state, whoever set it.
  - E4 applies under every ★1 option.
  - It covers a recorded-state change by anyone and, as §2.9 states, a campaign-membership copy reached through any same-org call on the identity, an out-of-scope agent's call included. The security review must confirm this (D5-17).
  - Out-of-scope calls and sales on the identity are not credited in scope and change nothing else.
- **Never exposed:** row identities, names, phone numbers, timestamps, other agents' rows, campaign names or metadata (the state reader returns none) and cross-organization data.
- **Review gate.** A named security reviewer reviews the actual SQL of the state reader and its helpers, with the S1–S15, S14a and S14b results, on the exact commit. This happens before the reader bodies are frozen and before the PKG-A production approval (§2.9). This plan is not that sign-off.

### 3.8 Index and performance (§2.7)
- **Index.** `CREATE INDEX IF NOT EXISTS report_v3_lineage_original_lead ON private.dialer_conversion_lineage (organization_id, original_lead_id)` in `…14`. It is built transactionally, which §2.7 allows only for private tables. D3's lineage lookups use it too.
- **No new `campaign_leads` index.** It is a hot dialer table, and S3 touches only all-blank identities (at most 53 call rows live; re-measured at the preflight).
- **Gate.** D1's `reports_v3_performance.sql`:
  - load: 500k calls, 5k sales and 10k appointments per org;
  - settings: `SET LOCAL statement_timeout='8s'`;
  - target: state p95 ≤ 2 s, with EXPLAIN (ANALYZE, BUFFERS) recorded.

  The read-back fails on 57014 or on any reader above 4 s.
- **If the gate fails**, the remedy is a separately approved maintained identity table, never a timeout increase.

**`reports_v3_state_breakdown.sql`**
- **Classifier.**

  - A NULL-state client with a TX copy → TX by copy.
  - TX and OK copies → conflict.
  - Lead XX with a CA copy → invalid, with no fallback.
  - Lead CA + client NV → conflict.
  - Lead CA + client XX → CA.

  - Some usable premiums, one negative (invalid) → `partial/premium_invalid`.
  - Some usable premiums, missing and invalid mixed → `partial/premium_invalid`.
  - Every premium usable → `available`.
  - A sale recorded after `now()` is excluded from policies and AP, as in KPIs 1 and 2 (X14).
  - Outside sale: an AZ client with no calls → AZ policies 1, calls 0.
